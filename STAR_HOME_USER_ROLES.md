# STAR HOME — User Roles

Роль живёт в `Membership`, не в единственном поле пользователя. Один человек может быть жителем в одном объекте и сотрудником в другом.

Frontend роли не назначает и не считает их достаточным доказательством. API повторяет проверку на каждом действии.

## 1. Роли

| Роль | Область |
| --- | --- |
| `SUPER_ADMIN` | Платформа целиком |
| `COMPANY_ADMIN` | Все объекты своей компании |
| `OBJECT_ADMIN` | Один объект |
| `MANAGER` | Операционное управление объектом |
| `SECURITY` | Охрана и доступ объекта |
| `SERVICE_OPERATOR` | Заявки объекта |
| `RESIDENT` | Свои единицы недвижимости |
| `FAMILY_MEMBER` | Урезанный доступ к единице жителя |
| `GUEST` | Временный доступ, с `expiresAt` |

Роли `star-hub` (CEO, EDITOR, LAWYER и другие) к STAR HOME не переносятся.

## 2. Кто что может

`GUEST` видит только выданный временный доступ и теряет его после `expiresAt`.

## 3. Вход

Пользователь вводит логин и пароль. Посёлок на экране входа не выбирает.

```
Login
  → User
    → Membership[]
      → если одна единица: сразу «Мой дом»
      → если несколько: «Мои объекты»
      → если роль только административная: рабочий стол администратора
```

Человек с одной единицей и без админской роли не видит выбор объекта.

Человек, который и житель, и администратор, попадает в контекст по умолчанию из последней сессии. Переключение доступно, но не обязательно при каждом входе.

## 4. Экраны по роли в Phase 1

Два mock-профиля, чтобы утвердить два разных UX:

1. Житель Станислав — `RESIDENT` на Дом №24. Экран «Мой дом».
2. Администратор компании Star — `COMPANY_ADMIN`. Рабочий стол со списком объектов.

Оба профиля — фикстуры. Переключатель «войти как» на боевом логине не нужен: после настоящего входа маршрут выберет API. На Phase 1 допустим явный переход между тремя макетами, чтобы смотреть UX без backend.

## 5. Жизненные режимы и роли

Переключение Дома / На работе / В отпуске доступно жителю своей единицы и тем ролям, кому объект явно разрешил управление домом.

Гость режим дома не переключает.

Сотрудник охраны не видит эти три сценария как свой главный экран. Его инструмент — доступ и события. Этот экран не входит в Phase 1.
