## 2. Житель — mobile first

Главный вопрос: «Что происходит с моим домом прямо сейчас?»

### `/home` (расширение, не новый продукт)

Верх: STAR HOME, имя единицы («Дом №24»).

Статус: «Дом в порядке» / «Есть предупреждение» — как сейчас `houseReadout`, плюс stale/offline шлюза.

Плитки-факты, только если есть данные:

- Климат — температура, влажность
- Безопасность — датчики в норме / проблема
- Свет — «7 включено» или «нет данных»
- Двери — «все закрыты» или факт
- Энергия — если есть счётчик

Не выдумывать числа.

### Комнаты `/rooms`

Карточка комнаты из каталога, не из хардкода:

```
Гостиная
22,4°   46%
Свет · Вкл    Шторы · 70%
```

Пустая квартира без комнат — тихое состояние, как сейчас у не-HOUSE.

### Устройство `/devices/[id]` (новый)

Название, статус, одно главное действие.

- power: вкл/выкл
- brightness: ползунок
- thermostat: текущая / цель, − 22° +, режимы Auto Heat Cool Off
- curtain: открыть / закрыть / стоп
- gate: открыть / закрыть (существующий access API + confirm)
- OFFLINE: «Устройство недоступно», без кнопок-обманок успеха

1–2 касания. Без технических форм.

### Быстрые действия

На главной: выключить свет, закрыть шторы, закрыть ворота, «я уехал», «я дома».

«Я уехал» / «Я дома» = существующие `WORK` / `HOME`, не новые режимы.
`VACATION` остаётся третьим.
Ночь — сценарий внутри HOME, не Life Mode.

HIGH из быстрых действий — тот же confirm, что ворота сейчас.

### История `/devices/[id]/history` или секция на карточке

Точки для будущего графика. Phase 5 — список «08:00 — 21,8°», не обязательно график.

## 3. Админ — desktop first

Не жительский UI.

Новые разделы консоли (под «Системы», рядом с Инженерия / Устройства):

| Экран | Право | Содержание |
| --- | --- | --- |
| `/admin/smart-home` | `devices.view` | сводка объекта: шлюзы, устройства, алерты |
| `/admin/smart-home/gateways` | `engineering.view` | статус, last seen, адаптер, число устройств |
| `/admin/smart-home/devices` | `devices.view` + create/edit | реестр, фильтр, поиск, test command |
| `/admin/objects` дерево | `objects.structure.edit` | комнаты у единицы; планировка как сейчас |

Технические id, endpoint, ошибки — только здесь.

Существующие `/admin/devices` и `/admin/engineering` не выкидываем в Phase 0. Сводим в Phase 6, чтобы не плодить три списка устройств.

Охрана по-прежнему видит ворота и камеры, не климат чужой гостиной.

## 4. Комнаты в Object Builder

В карточке дома/квартиры: список помещений, этаж если `floors > 1`.
Планировка уже грузится картинкой — слоты «1 этаж» / «2 этаж».
Интерактивные кнопки на плане — **после** реестра устройств, отдельным подтверждением. В Phase 1–5 только сущность комнаты и привязка `roomId`.

## 5. Чего не делать в UI

- Generic IoT dashboard, неон, SCADA-таблицы жителю
- Показ MQTT / IP / device id в PWA
- Фейковые датчики «для красоты»
- Четвёртый переключатель режима жизни
- Отдельное native-приложение
