# STAR HOME — Object Model

Одна иерархия для посёлка, жилого комплекса, апартаментов и любого следующего типа. Отдельные схемы под тип недвижимости не создаются.

## 1. Иерархия

```
Company
  └── Object
        └── Building     необязателен
              └── Unit
                    └── человек через Membership
```

Коттеджный посёлок:

```
Company → Object → Unit
КП «Сияние» → Дом №1, Дом №2, Дом №24
```

Жилой комплекс и апартаменты:

```
Company → Object → Building → Unit
ЖК Парк Лайт → Корпус 1 → Квартира 101
Sky Residence → Корпус A → Апартамент 501
```

Отсутствие Building — нормальная конфигурация, не особый тип кода.

## 2. Company

Компания владеет объектами, сотрудниками и настройками.

- `id`
- `name`
- `status`
- `settings`
- `createdAt`
- `updatedAt`

Одна компания может иметь 1, 10, 100 или 1000 объектов в той же базе. Изоляция описана в `STAR_HOME_MULTITENANCY.md`.

## 3. Object

Универсальная сущность объекта.

`ObjectType`:

- `COTTAGE_COMMUNITY`
- `RESIDENTIAL_COMPLEX`
- `APARTMENT_COMPLEX`
- `APARTMENT_BUILDING`
- `MULTI_FAMILY_BUILDING`
- `CUSTOM`

Поля:

- `id`
- `companyId`
- `name`
- `type`
- `address`
- `description`
- `logo`
- `cover`
- `status`
- `settings`
- `createdAt`
- `updatedAt`

`type` меняет подписи в Object Builder («Дома», «Корпуса», «Квартиры»), не ветвление платформы. Подпись хранится в настройках объекта, а не в условии по имени.

## 4. Building

Необязательный уровень.

- `id`
- `objectId`
- `name`
- `number`
- `address`
- `floors`
- `status`
- `metadata`

## 5. Unit

Конкретная единица: дом, квартира, апартамент, таунхаус, помещение, офис, парковка.

`UnitType`:

- `HOUSE`
- `APARTMENT`
- `APARTMENT_UNIT`
- `TOWNHOUSE`
- `ROOM`
- `PARKING`
- `CUSTOM`

Поля:

- `id`
- `objectId`
- `buildingId` — nullable
- `name`
- `number`
- `type`
- `area`
- `floor`
- `status`
- `metadata`

## 6. Люди и связь с недвижимостью

Пользователь не равен жителю одного дома.

`User`: учётная запись, логин, пароль.

`Membership`: пользователь + компания + роль + необязательные `objectId` и `unitId`.

Один пользователь может иметь несколько membership:

- КП «Сияние», Дом №24, `RESIDENT`
- ЖК Парк Лайт, Корпус 2, Квартира 84, `RESIDENT`

Если membership с единицей недвижимости ровно один — приложение открывает её сразу.
Если несколько — экран «Мои объекты».

С Phase 4 житель — это `User` и membership с ролью `RESIDENT` на конкретную единицу. Администратор закрепляет человека за домом или квартирой. Тот же логин может получить вторую единицу в другом объекте: тогда после входа открывается «Мои объекты». Семья, машины и гости остаются следующими сущностями.

## 7. Life Mode

Ровно три значения:

- `HOME` — Дома
- `WORK` — На работе
- `VACATION` — В отпуске

Четвёртый режим не добавляется.

Температура, освещение, охрана и набор проверок — настройки объекта, не константы в интерфейсе. Значения `22`, `19`, `16` в код режимов не зашиваются.

Настройки режима:

- `objectId`
- `mode`
- `label`
- `climate`
- `lighting`
- `security`
- `notifications`
- `checks` — протечки, температура, электричество, доступ и другие включённые контроли

Экран показывает результат режима человеческим языком: «Комфортный режим», «Экономичный климат», «Усиленная защита».

С Phase 5 тексты и проверки хранятся на объекте. Житель переключает режим своей единицы, и выбор сохраняется. Четвёртый режим не появляется. Показание датчика и уставка режима — разные вещи.

## 8. Состояние дома для главного экрана

Снимок, который UI умеет показать. С Phase 6–9 гость, счёт и климат на главном экране берутся из пропусков, открытых счетов и показания устройства. Если записи нет, экран остаётся тихим.

- объект и единица: имя, тип
- активный `LifeMode`
- сводка: норма / требует внимания
- температура и влажность, если есть датчики
- статус защиты
- быстрые действия, разрешённые роли
- лента «Сегодня»: гость, счёт, событие, заявка

Категории для человека, не протоколы: освещение, климат, отопление, ворота, замки, камеры, движение, протечка, дым, пожар, электричество, вода, полив, шторы, счётчики.

## 9. Object Builder

Администратор собирает структуру визуально.

1. Название и `ObjectType`.
2. Если типу нужен корпус — список Building и действие «Добавить корпус».
3. Внутри объекта или корпуса — список Unit и действие с подписью из настроек: «Добавить дом», «Добавить квартиру», «Добавить апартамент».

Один компонент дерева. Разница только в данных: есть ли Building и какие подписи лежат в `settings`.

С Phase 3 каталог компании, объектов, корпусов и единиц хранит сервер. Кнопки «Добавить дом», «Добавить корпус», «Добавить квартиру» берут подпись из типа объекта. Создание в браузере без ответа сервера не считается сохранением. PostgreSQL сменит файл каталога позже, экран от этого не меняется.

## 10. Mock для Phase 1

Данные лежат в модуле фикстур и повторяют ответ API. Компоненты их не объявляют.

```ts
company: { id: "cmp_star", name: "Star" }

object: {
  id: "obj_siyanie",
  companyId: "cmp_star",
  name: "КП Сияние",
  type: "COTTAGE_COMMUNITY"
}

unit: {
  id: "unit_24",
  objectId: "obj_siyanie",
  buildingId: null,
  name: "Дом №24",
  number: "24",
  type: "HOUSE"
}

resident: { displayName: "Станислав" }

homeSnapshot: {
  lifeMode: "HOME",
  summary: "Всё в норме",
  temperatureC: 22.4,
  humidityPercent: 48,
  security: "ACTIVE"
}

today: {
  visitors: 1,
  balance: { amount: 12450, currency: "RUB" }
}
```

В админском обзоре того же объекта, отдельным ответом:

- 55 домов
- 128 жителей
- 7 гостей
- 2 заявки
- 0 тревог

Рядом в списке объектов — примеры другой формы, чтобы UI не выглядел как экран одного посёлка:

- ЖК Парк Лайт, `RESIDENTIAL_COMPLEX`, 3 корпуса, 248 квартир
- Sky Residence, `APARTMENT_COMPLEX`, 2 корпуса, 96 апартаментов

Эти карточки тоже приходят из фикстуры списка объектов, не из веток `if (type)`.

## 11. Остальные сущности базы

Вводятся по фазам, не сейчас:

`Device`, `DeviceState`, `Automation`, `AccessEvent`, `SecurityEvent`, `Payment`, `Invoice`, `Meter`, `MeterReading`, `ServiceRequest`, `Notification`, `AIConversation`, `AIMessage`, `AuditLog`.

`ServiceRequest.status`: создана, принята, назначена, в работе, ожидает, выполнена, закрыта.

Категории заявок: электричество, вода, отопление, уборка, территория, охрана, интернет, ремонт, другое.
